# LexiBot

Telegram-словарь с карточками и интервальным повторением.

## Запуск через Docker

1. Создайте бота через `@BotFather` и получите токен.
2. Создайте файл настроек:

   ```bash
   cp .env.example .env
   ```

3. В `.env` замените `BOT_TOKEN`, `OPENAI_API_KEY` и `POSTGRES_PASSWORD`.
   `REMINDER_TIMEZONE` задаёт таймзону ежедневных напоминаний, например
   `Europe/Moscow`. Значение `DATABASE_URL` используется только при локальном
   запуске без Docker.
4. Запустите PostgreSQL и бота:

   ```bash
   docker compose up -d --build
   ```

Проверить состояние и посмотреть журнал:

```bash
docker compose ps
docker compose logs -f bot
```

Данные PostgreSQL сохраняются в отдельном Docker-томе и не исчезают при
пересборке контейнера.

## Размещение на VPS

Для Ubuntu-сервера достаточно установленного Docker с Compose:

```bash
git clone <адрес-репозитория> lexibot
cd lexibot
cp .env.example .env
nano .env
docker compose up -d --build
```

Порт PostgreSQL наружу не публикуется: база доступна только боту внутри Docker-сети.
Контейнеры автоматически запускаются после перезагрузки сервера и
перезапускаются при сбое.

Обновление приложения:

```bash
git pull
docker compose up -d --build
```

Рекомендуемый минимум для VPS: Ubuntu 24.04, 1 CPU, 1 GB RAM и 10 GB диска.
Для резервной копии базы:

```bash
docker compose exec -T postgres pg_dump -U lexibot lexibot > lexibot-backup.sql
```

## Автоматический деплой через GitHub Actions

Workflow `.github/workflows/deploy.yml` запускается после каждого push в `main`.
Сначала он проверяет синтаксис, тесты и Compose-конфигурацию. После успешных
проверок GitHub подключается к VPS по SSH, выполняет fast-forward обновление
репозитория, собирает образ и проверяет, что PostgreSQL здоров, а бот запущен.

### 1. Создание отдельного SSH-ключа

На своём компьютере создайте ключ без пароля специально для GitHub Actions:

```bash
ssh-keygen -t ed25519 -C "github-actions-lexibot" -f lexibot_deploy_key
```

Добавьте содержимое `lexibot_deploy_key.pub` в `~/.ssh/authorized_keys`
пользователя деплоя на VPS. Этот пользователь должен иметь доступ к каталогу
проекта, репозиторию GitHub и команде `docker compose`.

### 2. GitHub Environment и secrets

В репозитории откройте `Settings → Environments`, создайте environment
`production`, затем добавьте в него secrets:

| Secret | Значение |
| --- | --- |
| `VPS_HOST` | IP-адрес или домен VPS |
| `VPS_PORT` | SSH-порт; необязателен, по умолчанию `22` |
| `VPS_USER` | SSH-пользователь для деплоя |
| `VPS_DEPLOY_PATH` | Полный путь к клону, например `/opt/lexibot` |
| `VPS_SSH_KEY` | Полное содержимое приватного `lexibot_deploy_key` |
| `VPS_KNOWN_HOSTS` | Проверенный публичный fingerprint SSH-сервера |

Получить `VPS_KNOWN_HOSTS` следует с доверенного компьютера:

```bash
ssh-keyscan -p 22 your-vps.example.com
```

Сверьте fingerprint с выводом `/etc/ssh/ssh_host_ed25519_key.pub` на VPS перед
добавлением. Не используйте отключение `StrictHostKeyChecking`.

Секреты приложения (`BOT_TOKEN`, `OPENAI_API_KEY`, пароль PostgreSQL) остаются
только в `/opt/lexibot/.env` на VPS. GitHub Actions их не получает.

### 3. Первый запуск

Убедитесь, что на VPS уже существует клон репозитория на ветке `main`, файл
`.env` заполнен, а ручной `docker compose up -d --build` работает. После этого
push в `main` запустит автоматический деплой. Его также можно запустить вручную
на вкладке `Actions → Test and deploy → Run workflow`.

## Локальный запуск без Docker

Нужен работающий PostgreSQL, соответствующий `DATABASE_URL` из `.env`:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m lexibot
```

## Команды MVP

- `/addnew` — добавить слово и пользовательский комментарий;
- `/addnew word` — добавить слово, затем указать комментарий;
- `/list` — группы и слова пользователя;
- `/study` — повторить карточки, срок которых наступил;
- `/stats` — статистика слов и серия дней подряд;
- `/edit` или `/edit word` — изменить слово, перевод или группу;
- `/delete` или `/delete word` — удалить карточку с подтверждением;
- `/settings` — изменить язык, цель, уровень и время напоминания;
- `/cancel` — отменить текущий ввод;
- `/help` — справка.

Бот работает в двух независимых режимах: English и Español. Активный режим
выбирается кнопкой в главном меню и сохраняется отдельно для каждого пользователя.
Списки, добавление и повторение показывают карточки только выбранного языка.

При добавлении пользователь вводит слово и необязательный комментарий. OpenAI
создаёт нормализованное слово, пример предложения, объяснение на изучаемом языке
и перевод на русский. Генерация учитывает цель и уровень пользователя:
для путешествий бот просит больше travel-контекста, для работы — business-примеры,
для экзамена — более академичные формулировки, а уровень влияет на сложность
примеров и объяснений. Изучаемое слово в примере выделяется жирным. Кнопка
«🔊 Произнести» создаёт MP3 с произношением через Google TTS. Во время
повторения бот случайно выбирает один из форматов проверки: слово → перевод,
перевод → слово или объяснение → слово. После нажатия «Показать ответ» бот
показывает всю карточку и предлагает оценить, насколько легко она вспомнилась.

После первого `/start` бот проводит пользователя через короткий онбординг:
выбор языка, цели (работа, путешествия, подготовка к экзамену или общее
обучение), уровня и удобного времени напоминания. Эти настройки можно
поменять через `/settings` или кнопку «⚙️ Настройки». Основные действия также
доступны через постоянное меню в нижней части чата. Во время добавления и
редактирования меню заменяется кнопкой отмены.

Фоновый планировщик внутри бота проверяет напоминания раз в
`REMINDER_CHECK_INTERVAL_SECONDS` секунд. Если у пользователя наступило выбранное
время, есть карточки к повторению и сегодня бот ещё не напоминал, он отправит
сообщение с кнопкой меню. Если карточек к повторению нет, напоминание не
отправляется.

Раздел «📊 Статистика» показывает количество слов по уровням: новые, плохо
выученные, хорошо выученные, почти выученные и выученные. Также бот считает
серию дней подряд. День засчитывается после повторения хотя бы одной карточки:
до выполнения дня показывается серый кружок `⚪`, после выполнения — огонёк `🔥`.

У карточки пять уровней: новое слово, плохо выучено, хорошо выучено, отлично
(осталось одно повторение) и выучено. Карточки пятого уровня больше не попадают
в сессии `/study`. Интервалы повторения: 15 минут после ошибки, затем 1, 3, 7
и 30 дней по мере успешного изучения.
